# Nihonbuzz - AI Assistant Guidelines

This file contains project-specific rules for AI agents. For general information, refer to `README.md`.
Our architecture is heavily inspired by `dyzulk`'s Cloudflare setup, but specifically adapted to support a **Notion-like Japanese learning platform**.

---

## Project Context

**Nihonbuzz** adalah platform edukasi bahasa Jepang (JLPT N5-N3) dan media budaya yang beroperasi layaknya Notion. Pengguna tidak hanya membaca konten, tetapi berinteraksi dengan *blocks*, *pages*, dan *workspaces* untuk catatan belajar mereka.

Sistem berjalan di atas **Cloudflare Workers** menggunakan **Next.js App Router** via OpenNext. Arsitektur menggunakan Cloudflare primitives secara penuh tanpa server eksternal.

### Primary Stack

- **Runtime**: Next.js 16 App Router (React Server Components)
- **Deploy**: Cloudflare Workers via `@opennextjs/cloudflare`
- **Database**: Cloudflare D1 (SQLite) + Drizzle ORM
- **Cache**: Cloudflare KV (untuk ISR, session, edge caching)
- **Storage**: Cloudflare R2 (untuk media aset dan lampiran Notion-blocks)
- **Queue**: Cloudflare Queue (untuk task asinkron)
- **Email**: Cloudflare Email Worker (Workers Paid plan)
- **Styling**: Tailwind CSS v4 + Framer Motion / GSAP (untuk animasi mikro)
- **Language**: TypeScript (strict)
- **Package manager**: `pnpm`

---

## Notion-like Architecture Paradigm

Website ini berfungsi seperti Notion:
1. **Pages & Blocks**: UI tidak statis; konten direpresentasikan sebagai sekumpulan blocks (teks, gambar, vocab flashcards, kuis) dalam sebuah page.
2. **Workspaces**: Setiap pengguna memiliki personal workspace (notebook) untuk mengatur materi belajar.
3. **Database Relasional**: Data schema (Drizzle) harus mendukung struktur pohon/hierarki (parent-child pages) dan polymorphism untuk tipe blocks.

## Cloudflare Bindings & IDs

> ⚠️ Jangan pernah commit file `.dev.vars` atau secrets ke git. Gunakan `.env.production` hanya untuk placeholder/publik keys.

### Accessing Bindings in Code

```typescript
import { getCFContext } from "@/lib/cloudflare";

// Selalu gunakan wrapper ini untuk mengakses CF binding di server code
const { env } = await getCFContext();

// Contoh
const db = env.DB;         // D1
const r2 = env.R2_BUCKET;  // R2
```

### Wrangler Commands

```bash
# Generate TypeScript types setelah menambah binding
pnpm run cf-typegen

# Deploy ke Cloudflare Workers (CI/CD use this)
pnpm run build:workers
pnpm run deploy

# Jalankan dev server lokal
pnpm run dev
```

## General Coding Rules

- Tulis TypeScript yang ringkas dan teknikal. Hindari `any`.
- **Prefer functional dan declarative patterns**. Hindari `class`.
- Prefer named exports.
- Gunakan lowercase dengan dash untuk direktori: `my-feature/`.
- **Global types** ditambahkan di `custom-env.d.ts`, **bukan** `cloudflare-env.d.ts`.
- Desain UI harus *premium, minimalist, Vercel/Notion style* dengan tipografi yang kuat (Plus Jakarta Sans).

## Database & Migrations

Schema hidup di `src/db/schema.ts`. Berikut aturan wajib D1:

- ❌ **Jangan gunakan Drizzle transactions** — Cloudflare D1 tidak mendukungnya dengan baik dalam beberapa skenario.
- ❌ **Jangan pass `id` saat insert** — ID di-generate otomatis oleh schema (`cuid2`).
- ✅ Setelah ubah schema, jalankan: `pnpm run db:generate [NAMA]`

### Schema Patterns (Notion-like)

Setiap page dan block harus memiliki reference ke parent untuk membentuk hirarki.

```typescript
import { createId } from '@paralleldrive/cuid2';

const commonColumns = {
  createdAt: integer({ mode: "timestamp" }).$defaultFn(() => new Date()).notNull(),
  updatedAt: integer({ mode: "timestamp" }).$onUpdateFn(() => new Date()).notNull(),
};

// Contoh rancangan Block schema
export const blocksTable = sqliteTable("blocks", {
  ...commonColumns,
  id: text().primaryKey().$defaultFn(() => `blk_${createId()}`).notNull(),
  pageId: text().notNull(), // Foreign key to pages
  type: text().notNull(),   // 'text', 'heading', 'flashcard', 'kanji'
  content: text({ mode: "json" }), // Flexible payload
  order: integer().notNull(), // Urutan block di dalam page
});
```

## Authentication & State

- Gunakan session-based auth yang disimpan di **KV**.
- **Prefer Server Components** untuk data fetching awal (SSR).
- Untuk interaksi Notion-like editor (client-heavy), pisahkan state manajemen menggunakan hooks, namun selalu optimalkan *optimistic UI updates* saat sinkronisasi block ke server (via Server Actions).

### Server Actions

- Semua mutasi (seperti drag-and-drop block, update text) wajib memakai `actionClient` (next-safe-action).
- Define validasi dengan `.inputSchema(zodSchema)`.

## R2 (File Storage & Attachments)

Semua upload gambar/aset dalam Notion-blocks harus dikirim ke R2:

```typescript
const { env } = await getCFContext();
await env.R2_BUCKET.put(key, body, { httpMetadata: { contentType } });
```

---

## Queue (Background Jobs)

Gunakan Queue untuk memproses analitik belajar user, notifikasi email, atau generate ringkasan flashcard AI tanpa memblokir response thread.
